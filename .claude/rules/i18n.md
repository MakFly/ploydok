# i18n — copy UI

Toute copy user-visible **nouvelle ou modifiée** dans `apps/web` passe par i18next. Un littéral EN ou FR en dur dans le JSX / un toast est un bug.

## Stack

- `i18next` + `react-i18next`. Locales `en` | `fr`. Cookie `ploydok-locale`.
- Catalogues : `apps/web/src/locales/{en,fr}/*.json` (le disque est le registre).
- Composants : `useTranslation("ns")`. Libs / toasts : `i18n.t("ns:key")`.
- Close Dialog/Sheet : wrappers `apps/web/src/components/i18n/{dialog,sheet}.tsx`. Pas d'i18next dans `@workspace/ui`.

## Quand tu ajoutes de l'UI

1. Trouve le namespace (`common`, `auth`, `apps`, `settings`, …).
2. Ajoute la clé dans **en et fr** dans le même diff. Mêmes `{{var}}`, pas de valeur vide.
3. Branche `t("clé")` — ne laisse pas le texte en dur « le temps de traduire ».
4. `cd apps/web && bun test src/lib/i18n/` (parité + interpolations).

## Ne pas traduire

Noms d'env, tokens techniques (`Dockerfile`, `TOTP`, `OAuth`), logs bruts, commentaires, changelog Markdown, `error.message` API sans `code` mappé.
